RAG 설계 진화 기록

피트니스 챗봇 RAG 파이프라인의 설계가 단계별로 어떻게 발전했는지 정리한 문서입니다. (1) 데이터 파이프라인 → (6) recall 노드와 쿼리 재작성까지.

STEP 1

기획 단계 · 데이터 파이프라인

오프라인 인덱싱: 데이터 적재 → 분할 → 임베딩(OpenAI) → PostgreSQL(pgvector) 저장.

STEP 2

기본 LangGraph 구성

가장 단순한 형태 — 단일 retrieve 노드로 검색하고 generate로 답변을 생성.

STEP 3

조건 분기(conditional edge) 도입

classify를 추가해 질문 유형(general/specific/injury)별로 retrieve를 분기.

STEP 4

Adaptive RAG

운동 무관 질문용 out_of_scope, 복잡한 질문용 Multi-Query 확장 검색, 상태 관리용 RAGState를 도입.

STEP 5

recall 노드 추가

"처음 물어본 운동이 뭐야?" 같은 회상·메타 질문을 검색 없이 대화 기록만으로 답하도록 분리 — 검색 결과 오염 차단.

STEP 6

최종 · recall + query rewriting 강화

검색 경로는 검색 전 _rewrite_query로 "처음 물어본 운동"을 실제 운동명으로 치환 — "처음 물어본 운동의 호흡법"까지 정확히 처리.
