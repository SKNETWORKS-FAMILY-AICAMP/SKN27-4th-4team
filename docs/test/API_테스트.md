### 챗봇 LangGraph 노드 커버리지

현재 코드 기준 챗봇 LangGraph는 `classify -> retrieve_general/retrieve_specific/retrieve_injury -> generate` 또는 `classify -> out_of_scope -> END` 흐름입니다. 그림의 `recall`은 코드상 독립 노드로 등록되어 있지는 않고, `state.messages` 기반 히스토리와 `_rewrite_query()`를 통해 검색 노드 내부에서 동작합니다.

실제 API 테스트에서는 general, specific, injury, out_of_scope, history/rewrite 대표 질문이 모두 정상 응답했습니다. 다만 Docker stdout에서 `[classify]`, `[retrieve_*]`, `[rewrite_query]` 로그는 확인되지 않아, 노드별 라우팅은 코드 구조와 응답 결과 기준으로 판정했습니다.

| 확인 대상 | 직접 건드리는 질문 | 예상 흐름 | 확인 기준 |
|---|---|---|---|
| classify | 모든 챗봇 질문 | START -> classify | 서버 로그에 `[classify] 질문 유형: ...` 출력 |
| retrieve_general | 초보자는 주 몇 회 운동하는 게 좋아? | classify(general) -> retrieve_general -> generate | `[retrieve_general] 검색된 운동 수` 출력 |
| retrieve_general | 오늘 가슴 운동 추천해줘 | classify(general) -> retrieve_general -> generate | 카테고리 힌트가 가슴으로 잡히는지 확인 |
| retrieve_specific | 스쿼트랑 레그프레스는 어떤 차이가 있어? | classify(specific) -> retrieve_specific -> generate | `[retrieve_specific] 검색된 운동 수` 출력 |
| retrieve_specific | 랫풀다운 할 때 등보다 팔이 먼저 털리는데 어떻게 해야 해? | classify(specific) -> retrieve_specific -> generate | 특정 운동명 추출 후 검색되는지 확인 |
| retrieve_injury | 무릎이 아픈데 런지 계속해도 돼? | classify(injury) -> retrieve_injury -> generate | `[retrieve_injury] ... rerank 적용` 출력 |
| retrieve_injury | 허리디스크가 있는데 데드리프트 해도 돼? | classify(injury) -> retrieve_injury -> generate | 부상 주의 문구와 안전한 대체 안내 확인 |
| out_of_scope | 오늘 주식 뭐 사야 돼? | classify(out_of_scope) -> out_of_scope -> END | `운동 관련 질문만 답변할 수 있습니다.` 반환 |
| out_of_scope | 서울에서 제일 맛있는 라멘집 추천해줘 | classify(out_of_scope) -> out_of_scope -> END | 검색/generate 없이 즉시 종료 |
| recall/history | 오늘 가슴 운동 추천해줘 -> 방금 말한 운동 중 어깨 부담 적은 걸로 골라줘 | 1차 general, 2차 history 반영 후 general 또는 injury | 이전 답변의 운동명을 반영하는지 확인 |
| generate | general/specific/injury 질문 전체 | retrieve_* -> generate -> END | 검색된 운동 데이터 기반 최종 답변 생성 |

아래 질문 리스트는 위 노드 커버리지 표와 연결됩니다. `연결 노드`를 기준으로 어떤 질문이 어느 분기를 검증하는지 확인합니다.

| 구분 | 연결 노드 | 질문 | 기대 동작 |
|---|---|---|---|
| 운동 기본 지식 | retrieve_injury -> generate | 벤치프레스 할 때 어깨가 아픈데 자세를 어떻게 고쳐야 해? | 통증 키워드가 있으므로 부상/통증 분기로 처리하고 자세 주의점, 중단/전문가 상담을 안내 |
| 운동 기본 지식 | retrieve_specific -> generate | 스쿼트랑 레그프레스는 어떤 차이가 있어? | 특정 운동명 2개를 인식하고 자극 부위, 난이도, 장단점을 비교 |
| 운동 기본 지식 | retrieve_injury -> generate | 데드리프트 할 때 허리가 말리는 이유가 뭐야? | 허리 통증/부상 위험 맥락으로 보고 원인과 교정 포인트, 무리한 중량 회피를 안내 |
| 운동 기본 지식 | retrieve_specific -> generate | 랫풀다운 할 때 등보다 팔이 먼저 털리는데 어떻게 해야 해? | 특정 운동명 추출 후 그립, 견갑 움직임, 팔 개입 줄이는 방법을 안내 |
| 루틴/운동 계획 | retrieve_general -> generate | 초보자는 주 몇 회 운동하는 게 좋아? | 일반 운동 계획 질문으로 분류하고 초보자 기준 빈도와 회복 필요성을 설명 |
| 루틴/운동 계획 | retrieve_general -> generate | 근비대 목적이면 8회랑 15회 중 뭐가 더 좋아? | 일반 운동 지식으로 분류하고 반복수보다 점진적 과부하와 볼륨이 중요하다고 설명 |
| 루틴/운동 계획 | retrieve_general -> generate | 유산소는 웨이트 전이 좋아 후가 좋아? | 목표별로 전/후 배치 기준을 설명 |
| 루틴/운동 계획 | retrieve_general 또는 retrieve_injury -> generate | 하체 운동 다음날 달리기 해도 돼? | 피로도와 강도에 따라 조절하라고 안내 |
| 통증/주의 질문 | retrieve_injury -> generate | 무릎이 아픈데 런지 계속해도 돼? | 통증 지속 시 중단을 안내하고 대체 동작/전문가 상담을 권장 |
| 통증/주의 질문 | retrieve_injury -> generate | 손목이 아픈데 푸쉬업을 어떻게 바꾸면 좋아? | 손목 부담을 줄이는 변형 동작을 제안 |
| 통증/주의 질문 | retrieve_injury -> generate | 허리디스크가 있는데 데드리프트 해도 돼? | 의료 판단을 단정하지 않고 전문가 상담과 저부하 대안을 안내 |
| 식단 관련 | retrieve_general -> generate | 근육 키우려면 단백질을 얼마나 먹어야 해? | 일반 운동/식단 질문으로 처리하고 단백질 섭취 기준과 개인차를 안내 |
| 식단 관련 | retrieve_general -> generate | 운동 전에 밥 먹는 게 좋아? | 소화 시간과 운동 강도에 따른 식사 타이밍을 설명 |
| 서비스 사용 | retrieve_general -> generate | 내가 저장한 루틴은 어디서 볼 수 있어? | 앱 기능 질문으로 처리하고 저장 루틴 확인 경로를 안내 |
| 서비스 사용 | retrieve_general -> generate | 추천 루틴이 마음에 안 들면 바꿀 수 있어? | 피드백을 통해 수정 요청할 수 있음을 안내 |
| 맥락 유지 1 | retrieve_general -> generate | 오늘 가슴 운동 추천해줘 | 가슴 카테고리 힌트를 잡고 가슴 운동 예시를 제안 |
| 맥락 유지 2 | recall/history + rewrite_query -> retrieve_general 또는 retrieve_injury -> generate | 방금 말한 운동 중에 어깨 부담 적은 걸로만 다시 골라줘 | 이전 응답 맥락을 반영해 어깨 부담이 적은 운동으로 재정리 |
| 모호한 질문 | retrieve_general -> generate | 나 운동 뭐 해야 돼? | 애매한 운동 질문은 general로 분류하고 목표, 수준, 통증, 가능 시간 등 추가 정보를 질문 |

| 비운동 건강 질문 | retrieve_general 또는 retrieve_injury -> generate | 감기 걸렸는데 운동해도 돼? | 증상에 따라 휴식을 권하고 의료 조언을 단정하지 않음 |

## 우선순위

1. 인증/계정: 회원가입, 로그인, 중복 검증, 비밀번호 정책은 서비스 진입 조건이므로 최우선입니다.
2. 챗봇: LLM 응답, 세션 유지, 오류 처리가 사용자 체감 품질에 직접 연결됩니다.
3. 운동 정보 조회: 운동 목록/상세/검색은 추천 외 기능의 기본 데이터 흐름입니다.
4. 루틴 저장/조회: 추천 생성과 분리해 저장된 결과를 안전하게 조회할 수 있는지 확인합니다.
5. 프론트엔드 공통 흐름: 새로고침, 비로그인 접근, 실패 표시를 마지막으로 확인합니다.
