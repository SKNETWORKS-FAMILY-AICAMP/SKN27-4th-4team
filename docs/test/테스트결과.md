# 테스트 결과 종합

HELBOTIN의 테스트는 API 기능 검증과 배포 화면 기준 수동 UI 검증으로 나누어 진행했습니다. API 테스트는 서비스 핵심 기능의 응답과 권한 처리를 확인했고, 화면 테스트는 실제 배포 환경에서 버튼, 라우팅, 모달, SSE 응답, 영상 로딩, 반응형 상태를 확인했습니다.

| 루틴 추천/UI 흐름 | 설문 입력, AI 추천 생성, 루틴 확인, 피드백 입력, 다시 설계, 저장 | 정상. 배포 화면에서 추천 생성 후 결과 화면 진입 확인 |
| 공통 UI | 네비게이션, 모달, 새로고침 세션 유지, 모바일 반응형, 콘솔 에러 | 정상. 홈/루틴 모바일 가로 overflow 없음, 콘솔 error/warn 없음 |

## 4. 주요 확인 사항

- 로그인/로그아웃, 중복 검증, 세션 유지 흐름은 정상 동작했습니다.
- 챗봇은 general, specific, injury, out_of_scope 유형 질문에 정상 응답했습니다.
- 운동 백과는 목록/상세/대표 운동 조회와 프론트 검색/필터 흐름이 정상 동작했습니다.
- 운동 상담 SSE 스트리밍 응답이 배포 환경에서 정상 표시되었습니다.
- 주간 루틴 AI 추천 생성 후 루틴 결과 화면으로 정상 진입했습니다.
- 운동 상세 영상 리소스가 정상 로드되었습니다.
- 모바일 화면에서 주요 페이지의 가로 overflow와 버튼 겹침이 확인되지 않았습니다.

## 5. 확인된 이슈

| 우선순위 | 이슈 | 영향 | 개선 방향 |
| --- | --- | --- | --- |
| 높음 | 비밀번호 길이 검증 미적용 | `Aa1!`처럼 8자 미만 비밀번호로 가입 가능 | 백엔드 회원가입 serializer/form에서 최소 길이 검증 추가 |
| 높음 | 비밀번호 조합 검증 미적용 | `passwordonly`처럼 숫자/특수문자 없는 비밀번호로 가입 가능 | 영어/숫자/특수문자 조합 정책을 서버 검증으로 강제 |
| 중간 | API 실패 표시의 프론트 검증 보완 필요 | API 404는 확인했으나 모든 실패 UI를 충분히 확인하지는 못함 | 네트워크 실패, 500 응답, LLM 오류 케이스별 화면 문구 점검 |
| 중간 | 통증/부상 조건의 후보 필터링 강화 필요 | 일부 추천 케이스에서 통증 조건이 후보 단계에서 완전 차단되지 않을 수 있음 | GraphDB 후보 검색 단계에서 통증/부하 필터를 더 강하게 적용 |
| 중간 | 고위험 루틴 추천 조합의 루프 방지 필요 | `health + lower_back + 짧은 세션` 같은 조건에서 검증 루프 위험 | validation rule 완화, 후보 부족 시 fallback 정책 추가 |

## 6. 결론

전체 157개 테스트 중 155개가 정상 통과했습니다. 운동 라이브러리, 챗봇, 루틴 추천, 루틴 저장/조회, 주요 화면 이동은 실제 사용 흐름 기준으로 정상 동작했습니다.

가장 먼저 보완할 부분은 회원가입 비밀번호 정책입니다. 프론트에서 안내하더라도 서버 검증이 없으면 우회 가입이 가능하므로, 인증 정책은 백엔드에서 반드시 강제해야 합니다. 이후 통증/부상 조건의 GraphDB 후보 필터링과 고위험 추천 케이스의 루프 방지 조건을 강화하면 서비스 안정성을 더 높일 수 있습니다.
